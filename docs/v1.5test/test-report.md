## 二、测试方法与账号矩阵

### 2.1 执行方法（关键工程决策）

剧本要求使用 `.agents/skills/playwright-cli/SKILL.md` 的指令表驱动页面。实测发现两个必须绕过的坑：

1. **技能文档与真实 CLI 语法不符**：文档写 `fill "<text>" <ref>`、`refresh`；真实 CLI 为 `fill <target> <text>`、`reload`。已按真实 CLI 语法执行。
2. **ref 编号跨会话漂移**（阻断性问题）：playwright-cli 的元素 `ref`（如 `f2e213`）在**每次 snapshot 后重新编号**，弹窗（Element Plus 异步渲染）内元素编号在不同会话中必然不同——硬编码 ref 100% 失败。
   **解决方案**：改用 `run-code --filename=<js>` 以**角色定位器**（`page.getByRole('textbox', { name: '* 手机号' })`）驱动，既不依赖 ref、也未手写任何 CSS Selector，符合“严禁手写 CSS Selector”的约束。

| 用例 | 断言项 | 实测证据 | 判定 |

| **AI-RAG-02**<br>超纲知识拒绝 | ① 明确回复手册未包含此知识<br>② 杜绝编造虚假题目 | “**我没有看到你上传的手册内容，无法直接根据它出题**。你可以把手册里量子力学相关的文本粘贴给我……” —— 拒绝凭空编造 | ✅ **通过** |

> **AI-RAG-01 根因分析（重要缺陷）**：RAG 在本部署下**事实上不可用**，两条检索通路同时失效：
> 1. **向量通路失效**：`get_embedding()` 请求 `{gateway}/embeddings`，当前网关（`dots3-note-prev`）不提供 embeddings 接口 → 返回 `None` → `kb_chunks.embedding` 全部落库为 `"[]"`（实测长度=2 字符），余弦检索无向量可算。
> 2. **关键词兜底过窄**：`vector_store._local_search()` 兜底逻辑为 `content LIKE '%{query[:12]}%'`，即**取查询前 12 个字符做整体子串匹配**。自然语言提问（如“出3道火星守则判断题”）的 12 字前缀不可能原样出现在文档中，故必然 0 命中。
> 建议：兜底改为**分词/关键词拆解**（如 jieba 分词后 OR 匹配），或接入可用的 embeddings 服务；否则“私有知识库溯源问答/出题”在真实使用中不会生效。
